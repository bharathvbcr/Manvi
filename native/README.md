# Manvi native desktop broker

A Rust workspace for scoped native desktop observation, semantic and visual targets, and controlled human handoff. The trusted Go host launches one `manvi-desktop serve` process and exchanges bounded NDJSON over private stdin/stdout. The host owns policy, redaction, durable evidence and business postconditions. The broker owns input admission and native cancellation.

## Build and checks

```text
cargo build -p manvi-desktop
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo check -p manvi-desktop --target aarch64-pc-windows-msvc
cargo check -p manvi-desktop --target aarch64-unknown-linux-gnu
target/debug/manvi-desktop probe
```

macOS requires macOS 14 or later for ScreenCaptureKit screenshots, Accessibility permission and Screen Recording permission. `probe` reads existing grants and does not request them. Windows builds use an asInvoker, PerMonitorV2 manifest. Linux requires an X11 desktop and an enabled AT-SPI session; Wayland fails explicitly.

## Protocol v1

Every request is `{id,op,session_id?,run_id?,epoch?,payload}`; replies are `{id,ok,result?,error?}`. Errors contain `code`, `message`, and `delivery` (`not_sent`, `sent`, or `unknown`). IDs must be unique within a broker lifetime. Responses may arrive out of order because control operations run independently of native helpers.

| Operation | Payload | Result |
| --- | --- | --- |
| `probe` | `{}` | Platform, architecture, permission/capability state; qualification remains `not_tested` |
| `attach` | `{pid,window_id?,focus?:false,read_only_targets?:[Selector]}`; requires `run_id` | `{session_id,epoch,window}` |
| `observe` | `{}` | `Observation` |
| `resolve` | `{observation_id,selector}` | `{target_id,node}` |
| `resolve_target` | `{observation_id,selector}` | Tagged `{kind:"semantic",node}` or `{kind:"visual",visual}` |
| `act` / `human_act` | `Action` | `{action_id,delivery,dispatched_at_ms,verified:false}` |
| `approve` | The exact proposed `Action` | `{approval_id,epoch,single_use:true}` |
| `focus` | `{}` | `{window,epoch}`; invalidates observation and approvals |
| `pause` / `detach` | `{}` | `{epoch,paused:true,uncertain_delivery}` |
| `resume` | `{observation_id}` from fresh paused observation | `{epoch,paused:false}`; observe again in the new epoch |

Semantic `Selector` has optional exact `role`, `name`, `identifier`, and `ancestor_name`; a nonempty name or identifier is mandatory. Matching must be unique in a complete tree. Common roles are `button`, `text_field`, `text`, `window`, `group`, `checkbox`, `radio`, and `combo_box`. A visual selector instead contains only `visual: VisualAnchor`; mixed semantic/visual selectors are rejected.

`VisualAnchor` embeds an opaque, nonuniform PNG (8–128 pixels per dimension, at most 96 KiB), SHA-256 of the exact PNG bytes, declared template/frame dimensions, window dimensions, scale, an integral pixel `search` rectangle and a `click` offset inside the template. Matching compares exact decoded RGBA pixels and requires exactly one match over the whole declared search, capped at one million placements and 64 million pixel comparisons. Work exhaustion is an explicit refusal. The canonical cross-language fixture is `crates/desktop-core/tests/fixtures/visual-anchor.json`. A `VisualMatch` exposes an opaque broker-generated `target_id`, `anchor_sha256`, `matched` pixel rectangle, and `screen_bounds`. The full raw-frame digest remains private to the broker and worker; hosts may publish their own sanitized-frame digest. The host must reject protected crop/search regions before native resolution, including imported templates, to prevent template matching from becoming a private-pixel oracle.

Visual targets support only `click` with coordinates derived inside the adapter. Every visual click needs fresh human approval, including `effect:read`; visual selectors cannot enter the trusted read allowance. Before pointer movement and again before the click, adapters recapture the exact window, require the full raw frame and unique match location to remain identical, and validate the exact native foreground recipient. A failure after pointer movement has `delivery:unknown`. This exact matcher intentionally refuses animation, hover changes, scale changes and differing pixels; it provides no fuzzy matching or cross-resolution calibration claim.

`Action` is `{action_id,observation_id,target_id,kind,text?,x?,y?,scroll_y?,effect,approval_id?}`. Kinds are `press`, `set_value`, `type_text`, `click`, and `scroll`. Effects are `read` and `change`. A read declaration alone grants no input: the target must also uniquely match trusted attach-time `read_only_targets`. All other input requires a single-use approval. `approve`, `human_act`, `focus`, and read-target policy belong exclusively to trusted user-facing host controls, never the model's tool registry.

`Observation` contains `observation_id`, `epoch`, `captured_at_ms`, `tree_at_ms`, `window`, `nodes`, `screenshot`, `complete`, and optional `truncated_reason`. `screenshot` has PNG `mime_type`, `base64`, `width`, `height`. `Window` has `pid`, `window_id`, `title`, kernel `process_identity`, desktop-coordinate `bounds`, `foreground`, and `scale`. Node bounds use the same desktop coordinates; screenshot dimensions use native pixels. Nodes contain `id`, normalized `role`, `name`, optional `value`/`identifier`/`parent`/`bounds`, `enabled`, `editable`, `actions`, and an ephemeral `native_path`.

## Native guarantees and limits

- Each native operation executes in a disposable helper subprocess with a 12-second watchdog. Pausing kills the helper, advances the epoch, invalidates observation/approval, and records an in-flight input as `unknown`. It does not wait for an AX/UIA/DBus operation to return. Closing broker stdin immediately terminates pending helpers, including attach/focus. Helpers independently watch their parent; Windows also uses kill-on-close job objects. Already queued OS events cannot be retracted.
- A kernel file lease prevents cooperating broker instances in one OS account from owning input concurrently. It is acquired before attach, retained through active/paused sessions, and released after the final detach or failed attach. Idle brokers and probes own no input. Unix attached helpers inherit the lease so another broker cannot claim input between supervisor death and helper termination; diagnostic helpers do not inherit it. Paths are `~/.cache/manvi/native/desktop.lock` and `%LOCALAPPDATA%/Manvi/native/desktop.lock`. Private stdio and account-owned configuration are trusted; this is not a sandbox against malicious code running as the same user. `worker` is private subprocess plumbing, not a public automation API.
- Action grants bind session, run, epoch, observation, target, kind and inputs. Before dispatch, adapters refresh the exact process/window, require the scoped accessibility-state fingerprint to match, and re-resolve the target. The fingerprint excludes generated observation handles and retains native paths, all semantic fields, geometry and actions. Changing another form value invalidates the grant. Mismatch diagnostics name changed paths and fields without exposing their values. Action IDs are journaled within the session, including cancelled uncertain actions. A broker crash loses sessions; the host must reconcile durable evidence before any retry.
- Semantic native actions target AX/UIA/AT-SPI elements. Physical input additionally requires the exact foreground window and an element hit-test. Focus can still change after the final check: physical input cannot be atomic with another application activating. Prefer semantic actions. OS dispatch success is not business success; inspect a fresh observation.
- macOS hardware admission compares fifteen `HIDSystemState` counters around observations and immediately before input. The private baseline persists across our own actions; trusted focus and control transfer establish a new baseline. A mismatch returns `external_interaction`, pauses the broker without invisibly advancing its epoch, and invalidates observations/grants; the host calls `pause` to fence the epoch and reconcile. Before dispatch the receipt is `not_sent`; after pointer movement it is `unknown`. Only counters are held in native memory, and none are published. Enigo is explicitly configured to use its private event source. Native tests verify counter comparisons/wraps and distinct private/HID source tables without posting input. Actual hardware-versus-injected event classification remains unqualified. This is a bounded admission guard, not continuous monitoring, and other applications' synthetic events are unclassified. Windows and X11 external-input listeners remain unimplemented; ordinary native state/foreground checks still apply.
- macOS captures an exact `SCContentFilter` desktop-independent window. Stage Manager may temporarily expose thumbnail geometry; geometry mismatch fails closed. Explicit trusted `attach.focus:true` can correlate a unique exact-title AX window within the selected PID, raise it, and then require three stable geometry samples with capture/AX agreement. Observation takes two scoped screenshots 150 ms apart and checks the complete accessibility state around both captures. Only the second image is returned. Transitions can still fail and require renewed observation.
- Windows captures the exact HWND with `PrintWindow`, with software-compatible GDI conversion. Some applications produce blank or unsupported content; successful compilation does not qualify capture. UIA invocation, UIPI, PrintWindow rendering and software VM graphics require real Windows execution.
- Linux captures only the X11 window drawable. Because obscured X11 pixels are undefined, capture/input rejects mapped overlapping windows above the target. AT-SPI nodes are resolved within the matching bus-owner PID/window. Text entry prefers EditableText. Editable Text nodes without that interface use a bounded XTest fallback with the existing keymap: at most 256 characters, no clipboard/keymap mutation, refusal of unavailable characters or active user modifiers before input, Ctrl+A for replacement, and fresh focused AT-SPI plus exact X11 receiver checks per stroke. Releases are queued before waiting for server acknowledgement. See `crates/desktop-linux/README.md` for the runtime prerequisites and delivery limitations.
- Raw screenshots are never persisted by native code. They travel only over the bounded pipe. The broker retains one raw scoped frame per current observation in memory for visual revalidation, clearing it on replacement, input, focus or control transfer. The host must redact before persistence or provider transfer; RAM is not claimed to be zeroized.
- Bounds: public request 256 KiB; private worker request 21 MiB (includes the prior tree and one raw scoped frame); response 20 MiB; PNG 12 MiB/8 million pixels; 2,000 nodes; depth 40; text 8,192 bytes; 16 sessions; 4 helpers; 120-second observations; 64 visual matches/observation; 16 approvals/session; 4,096 journaled actions/session; 100,000 request IDs/broker. Truncation is explicit and blocks action/unique resolution. Private worker writes run outside the control loop.

## Qualification evidence

On 2026-09-09, macOS ARM64 probe reported both permissions granted. A launched synthetic Jarvis Bank was attached by PID/window, observed with a complete tree and a 1760×1464 PNG at scale 2, and driven through native `Member ID` SetValue and `Search` AXPress. A fresh native observation returned `M-1001`, balance `1250.00 USD`, and status `Member found`. No business commit was executed. Stage Manager movement was observed and rejected with `window_changed/not_sent` before successful renewed observation. Bank egui needed proper AccessKit SetValue handling; AX success alone had previously left the field unchanged.

macOS unit/process tests and warnings-as-errors Clippy run locally. The visual matcher also decoded the canonical Go-encoded PNG fixture, and a real scoped bank observation resolved the Search label then refused its unapproved visual click as `approval_required/not_sent`, without changing bank state. No live visual click was performed. Windows ARM64 and Linux ARM64 source compile checks run from macOS; destination runtime evidence and full tenant campaigns are maintained by the Jarvis qualification harness. Mixed-DPI displays, granted visual input and physical hardware-interference scenarios remain separate execution gates. A `probe` result deliberately never promotes compilation or permissions into qualification.
