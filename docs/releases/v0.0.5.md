# MANVI v0.0.5

MANVI v0.0.5 consolidates legacy package migrations, enhances automation with human takeover verification, adds workbench storage operations, and upgrades GitHub Actions release pipelines. It also narrows the macOS input guard by what an input can actually commit, makes offline deterministic replay accept its own journals, and follows DevCouncil's retirement of two verification switches that never switched anything. Local install stays stamped `v0.0.5`.

## Highlights

### 1. Legacy Package Migration & Canonical Crates
- Migrated legacy `dc`, `gate`, and `policy` packages.
- Symlinked canonical analysis crates at DevCouncil `rust/{dc-glob,dc-grep,dc-store,dc-verify,dc-evidence}` after the rust-port flatten, and `dc-proc` alongside them once `dc-verify` took a path dependency on it.
- Hardened enhancement JSON extraction so constraint sentences survive fenced or prefixed model output.

### 2. Upgraded GitHub Actions Release Workflows
- Updated `actions/download-artifact` to `v8.0.1` (`3e5f45b2cfb9172054b4087a40e8e0b5a5461e7c`).
- Updated `softprops/action-gh-release` to `v3.0.3` (`efb35369e0ad2afab669f228072c1b0d510eae64`).
- All GitHub Actions pinned by commit SHA with version tags tracked in comments.

### 3. Jarvis Automation & Human Takeover Verification
- Added locator ladders, outcomes, recoveries, overlays, and catalog gating for Jarvis.
- Revalidated human takeover against reviewed frames prior to input injection.
- Support for fenced enhancement JSON envelopes and Gemini recording proxy promotion.

### 4. Profile Workbench Storage & Host Operations
- Persistent workspaces, board items, enhancement proposals, automation schedules, and run records via `dc-store`.
- Opt-in `work.*` host operations advertised when `manvi serve --workbench-db` is set.
- Documented in [WORKBENCH.md](../WORKBENCH.md).

### 5. Computer-Use Foundations & Native Desktop Broker
- Multimodal tool execution with typed image/text blocks.
- Native desktop broker `manvi-desktop` built with Rust and driven over NDJSON stdio.
- Workflow capability compiler in `manvi/workflow`.

### 6. macOS Input Guard Partitioned by What the Input Can Commit
- The guard demanded exact equality across all fifteen `HIDSystemState` counters, `MouseMoved` included, so anyone touching the mouse aborted an otherwise valid run — a 40-run campaign suspended 17 times while all 40 independent saved-state checks passed.
- Counters are now partitioned by what the input behind them can do. Buttons, keys, modifiers, scroll and drags can commit an application state change and stay a hard refusal. `MouseMoved` and `TabletPointer` cannot press, type, scroll or drag, so element-addressed work (`observe`, `AXPress`, `AXValue`) reports them instead of aborting, and still revalidates the window, the scoped accessibility fingerprint and the target before dispatch.
- Coordinate-addressed input is unchanged: `TypeText`, `Click`, `Scroll` and every visual click still refuse motion, because there the pointer position is part of the action.
- **Security impact: this narrows the guard, it does not remove it.** No input that can change application state is newly admitted, and nothing bypasses pre-dispatch revalidation. Tolerated motion is recorded as `pointer_motion` on the observation and receipt, so evidence still shows a person was present; the field is omitted when nothing was observed, so quiet runs serialize exactly as before.
- Refusals now name the coarse input category that moved — `keyboard`, `scroll`, `drag` or `pointer_button` — deduplicated and ordered, so an operator can tell a person using the machine from a misfiring guard. The categories are deliberately coarse: no counts, keycodes, buttons or pointer coordinates reach the message, and a test asserts that.

### 7. Deterministic Replay Accepts Its Own Journals
- `NewState` allocated `RecoveryCounts` as an empty non-nil map while the field is tagged `omitempty`, so encoding dropped it and decoding yielded nil. A recorded trace never compared equal to a recomputed canonical admission, and offline deterministic replay rejected valid journals. `ResultFromState` had the same shape on `Result.Outputs`.
- Allocating only when non-empty restores round-trip equality and leaves the wire format byte-identical, so existing evidence bundles and their hashes stay valid.
- `roundtrip_test.go` pins the invariant for `State`, `Result` and `Event`, plus a reflective guard that fails any map or slice field tagged `omitempty` but allocated empty.
- `replay.Decode` takes fixture bytes and a source label, so a consumer can ship a fixture inside its binary; `replay.Load` now reads the file and delegates. Jarvis's `--provider fixture` rehearsal derived its transcript path from `runtime.Caller`, which under `-trimpath` resolves to a module-relative name that does not exist on disk — it worked under `go test` and failed in the shipped binary.
- `TransientObservation` names the re-observable capture failures once (`observation_inconsistent`, `window_changed`, `state_changed`, `window_ambiguous`, `window_occluded`), so the execution loop and callers outside it agree on what is worth retrying.

### 8. Two Verification Switches Retired (breaking)
- DevCouncil retired `verify.rigor.enabled` and `verify.diff_coverage.enforce` (`f7f427b`) as switches nothing read. Both were still read in `manvi/devcouncil`, so the package stopped compiling against a current sibling checkout.
- The reads are deleted rather than re-homed on a Manvi-owned key. The gates they named run in `dcverify`, reached by finding the binary; neither key ever decided whether a gate ran. A team that set `enforce: true` got no change in behaviour and a clean report.
- Both resolved to their defaults on every run that did not set them, and those defaults are now the whole behaviour: `stub_detection` findings are always kept, and an unmeasured or uncovered diff is always reported and never blocks.
- **Operator action:** a config file or `MANVI_*` variable still setting either key is now refused *by name* at startup. Remove `verify.rigor.enabled` and `verify.diff_coverage.enforce`. DevCouncil's own `verification.*` spellings in `.devcouncil/config.yaml` are unaffected and stay passed over.

## Installation & Verification

The local binary is built with version stamp `v0.0.5`:
```bash
go -C manvi build \
  -trimpath \
  -ldflags "-s -w -X main.stampedVersion=v0.0.5" \
  -o ~/.local/bin/manvi \
  ./cmd/manvi
```

The native desktop broker is a separate release build:
```bash
cargo build --manifest-path native/Cargo.toml --release -p manvi-desktop
```

Check the installed version:
```bash
manvi --version
```
Output reflects `v0.0.5 (-ldflags)` along with the current Git commit revision and clean tree state.
