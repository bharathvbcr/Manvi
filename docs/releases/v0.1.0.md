# MANVI v0.1.0

MANVI v0.1.0 is the first minor release. It adds the workbench host plane (task suggestion, refinement, gap scans and evidence-based verification on `manvi serve`), model tiers with an account-wide Anthropic spend cap, and tier escalation on evidence. It closes the read and secret gaps the v0.0.6 gate left open and makes long turns and sessions cost what their length is, not its square. The local install is stamped `v0.1.0`.

Two changes break compatibility. A workbench profile upgraded by this build is schema 13, which Manvi builds at earlier pins refuse. `manvi serve` refuses `devmap.*` and refine requests that carry no explicit repository root. Both are described below. The full list is under `[0.1.0]` in `CHANGELOG.md`.

## Highlights

### 1. The workbench host plane

These ops are enabled with `--workbench-db`, are host-only, and are listed in `contracts/serve.ops.schema.json`. A Go test fails when that file and the types disagree.

- `work.tasks.suggest` ranks the open board with a fixed, named point table and makes no model call.
- `work.enhancements.refine` proposes acceptance criteria, splits and duplicate links grounded in DevMap answers. It makes one model call, stores the proposal and applies nothing until `work.enhancements.accept`.
- `work.scan.gaps`, `work.scan.get` and `work.scan.cancel` run a deterministic audit (dead symbols, untested changes, open verification gaps, stale doc paths). A scan proposes inbox tasks and never writes the board.
- `work.verify.task` and `work.verify.get` return a `passed`, `failed` or `degraded` verdict from git, the rigor gates, the tests DevMap says reach the change, and a read-only critic scoring each acceptance criterion. Any check that could not run degrades the verdict. None reports a pass.
- `hello` reports each op's lane and deadline (`op_limits`). Blocking ops run on per-family lanes, so a stop is no longer queued behind a slow prepare. A full lane answers `E_BUSY` at once.

### 2. Model tiers and the spend cap

- Five tiers (`basic`, `lite`, `heavy`, `main`, `advisor`) each carry a model and an effort (`llm.tier.<tier>`, `llm.tier.<tier>.effort`). They are operator-scope settings only. A tier key in a repository `config.yaml` is refused. A session refuses to start, naming the tier, when a tier's model is unknown, unpriced under a cap, or cannot honour its effort. `manvi tiers` prints the resolved table, and `manvi agents` prints role → tier → model.
- `MANVI_ANTHROPIC_BUDGET_USD` sets one ledger shared by every session and project. A request whose worst case would pass the limit is refused before it is sent. Sub-agent fan-outs are admitted against the remaining headroom instead of being refused for the sum of their worst cases. Managed Claude agents do not inherit `ANTHROPIC_API_KEY` while a cap is set. `manvi budget` and `manvi budget reconcile` report and repair the ledger.
- A sub-agent that shows evidence of being out of its depth is re-run once on the next tier up, from a fresh conversation. Each fan-out shares one cap on these escalations.
- The usage line is priced per model. Steps no price table covers make the figure a lower bound, never `$0.00`.
- Claude Opus 5.5, Sonnet 5.5, Haiku 5.5 and Fable 5.1 are in the catalogue. Anthropic requests use automatic prompt caching. `ANTHROPIC_WORKSPACE_ID` is sent as `anthropic-workspace-id`.

### 3. Policy and secrets

- Every tool that can return repository bytes goes through one read gate (`devcouncil/readauth.go`). `get_diff`, `grep`, `git_show`, `read_file` and code-graph spans no longer leak a `.env`, including through a hard link.
- `command.secret_read` refuses `cat .env`, `cp secrets/x y` and `base64 < .env` in every posture except `yolo`. `devcouncil_git_commit` refuses staged content that holds a known credential under another name.
- A declared task scope fences every command that writes a file (`rm`, `truncate`, `dd of=`, `perl -i`, `rsync`, …), not only redirects. `command.operand.unverifiable` is a hard refusal everywhere.
- Secrets forwarded to MCP servers are scrubbed from their stderr. Every scrubber is built by one function.
- An unregistered sub-agent role runs read-only and is reported as `unknown_types`.

### 4. Speed

- An agent step no longer deep-copies the conversation through JSON. The copy is about 57× faster on a 300-message history, and what is sent to a provider is byte-for-byte unchanged.
- Session saves encode only new events. A 5000-event save allocates about 230 times instead of about 15,300.
- The TUI renders a streaming reply incrementally (a long reply: ~5 s and 2.4 GB → ~1 s and 51 MB). It draws at most 2,000 lines or 64 KiB of a tool result and repaints only while something animates.
- Untracked files in a diff take one `git diff` instead of one process each (258 git processes for 256 files became 5).

### 5. Correctness

- Provider streams that end without their terminal event fail with a retryable `transport.TruncatedStream` instead of settling as a complete, zero-usage response. Every provider bounds the wait for response headers.
- The TUI saves every turn of a session again. Builds before this saved only the first.
- Agent file writes are atomic (temporary sibling, fsync, rename).
- The TUI loop cannot deadlock on its own queue, and quitting waits for running turns to save.
- Read-only commands (`logo`, `flags`, `providers`, …) no longer create `.devcouncil/` or edit `.gitignore`. The managed ignore rules no longer reach past the harness's own state.
- `verify.sh` and CI no longer pass when a check failed or never ran.

### 6. Compatibility

- **Workbench schema 13.** The DevCouncil pin moves to wave 6. A profile this build upgrades is refused by a Manvi built at the previous pin with `schema_unsupported`, so move every host that shares a profile together. The upgrade runs only on a write, after a `<profile>.pre-schema-<N>.bak` backup. A read of an older profile is refused with `schema_upgrade_required` and leaves the file alone.
- **Explicit roots.** `devmap.status`, `devmap.query`, `work.enhancements.refine` and `work.verify.task` require an absolute, symlink-free git work-tree root. A missing or unusable root is `E_BAD_ROOT`.
- `MANVI_TEST_ALLOW_SKIP` is renamed `DEVCOUNCIL_TEST_ALLOW_SKIP`. The docs tooling installs with bun instead of npm.

## Installation & Verification

This build was verified against gusset `984209b` and DevCouncil `9add99c` (`scripts/module-pins.txt`). Sibling checkouts must be at those commits, and `scripts/check-release.mjs --tag` refuses any other. `manvi/go.mod` names `toolchain go1.26.9`.

This machine is darwin/arm64. The local binary is the engine-linked release build:

```bash
GOOS=darwin GOARCH=arm64 EVENT_NAME=workflow_dispatch INPUT_TAG=v0.1.0 \
  bash scripts/release-build.sh
cp dist/manvi-v0.1.0-darwin-arm64 ~/.local/bin/manvi
```

`scripts/release-build.sh` runs `gusset-check` before it accepts the artifact.

Check the installed version:

```bash
manvi --version
manvi gusset-check
```

`manvi --version` reports `v0.1.0 (-ldflags)` with the Git revision of the commit that was linked.

`native/` changed since v0.0.6 by refactoring only (shared error and bounded-text helpers moved into `desktop-core`, `cargo fmt`). The desktop broker is rebuilt from this commit and installed beside `manvi`:

```bash
cargo build --manifest-path native/Cargo.toml --release -p manvi-desktop
cp native/target/release/manvi-desktop ~/.local/bin/manvi-desktop
manvi-desktop probe
```

## Verifying a release download

Every release asset is listed in `SHA256SUMS`, and `PROVENANCE.json` records the commit, the workflow run, the passing `verify` run that gated the build, the pinned DevCouncil and gusset commits, the toolchain versions and each binary's digest.

```bash
shasum -a 256 -c SHA256SUMS --ignore-missing    # run in the download directory
jq -r '.run, .verify_run, .commit' PROVENANCE.json
gh run view <run id from .run> --repo bharathvbcr/Manvi   # the run must be the release workflow at .commit
```

These checks show that the files you hold are the ones that workflow run uploaded and that the commit passed `verify`. They are not a signature: `SHA256SUMS` and `PROVENANCE.json` are published beside the binaries by the same job, so they do not protect against someone who can replace release assets. The darwin binaries are not codesigned or notarized.
