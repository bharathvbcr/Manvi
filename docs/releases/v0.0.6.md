# MANVI v0.0.6

MANVI v0.0.6 links the Gusset engine into the release binary and makes that engine the policy matcher for a cgo build. The local install is stamped `v0.0.6`. This tree also contains the TMLR manuscript revisions that were on `paper/tmlr-route-a`; those commits do not change the `manvi` binary.

## Highlights

### 1. Release binaries link the Gusset engine

Shipped binaries were `CGO_ENABLED=0`, so the engine that now makes policy decisions was absent from everything that was published. Each target builds on a native runner. Linux binaries are fully static against musl through DevCouncil's `cgo-env.sh --target`. Every binary must pass its own `gusset-check` before it is accepted. Asset names are unchanged. `MANVI_RELEASE_ENGINE=0 scripts/release-build.sh` still builds the cgo-off binary for a local dry run.

macOS release binaries are linked for macOS 12.0 and refused if they record a newer minimum.

The module pins this was verified against are gusset `92c2056` and DevCouncil `3b58dd7` (`scripts/module-pins.txt`).

### 2. Policy decisions go through the engine in a cgo build

Every pattern question the write, read, and command ladders ask — secret paths, restricted and protected paths, planned-file globs, command allowlists — crosses into DevCouncil's dc-glob engine in `manvi serve`, in the attended session's gate, and in `manvi check`. Answers are held equal to fnmatch's by the CPython fixture, a fuzz differential through the boundary, and DevCouncil's policy suite re-run with the engine as every gate's default.

A matcher that cannot answer mid-decision is a hard denial under `path.engine_unavailable` / `command.engine_unavailable` (`contracts/verdict.schema.json`). A `CGO_ENABLED=0` build has no engine and keeps fnmatch.

A policy question the engine does not answer within 250 ms is answered by fnmatch instead of denied as `engine_unavailable`: a busy engine is not a broken one. `manvi` names a failed engine check on stderr at startup.

`devcouncil_git_stage` and `devcouncil_git_commit` ask the gate's matcher for the secret-path check. A matcher error refuses the stage or commit and says the check did not run.

A policy answer refused by the engine gate carries a fixed message. The engine's own error goes to stderr. `manvi serve` and `manvi gusset-check` drain the engine's Rust log ring to stderr.

### 3. `gusset-check` proves the panic firewall

`manvi gusset-check` runs `gussetcheck.SelfTest`: CPython fnmatch parity through the boundary, the batched match-any path, and a deliberate Rust panic inside the linked archive on a throwaway handle. That panic must come back as `ErrPanic`, then `ErrPoisoned`, while the shared handle keeps matching. Rust prints the induced panic to stderr; that line is the proof running. The policy plane's `Ready` still runs the panic-free `Run`.

`manvi serve` releases the engine handle on exit through `gussetcheck.Shutdown(2s)`. Jobs are cancelled and the join is bounded. A stuck engine is reported as a shutdown error and left to process exit.

`gussetcheck.Ready` no longer caches a transient failure for the life of the process. A pass is kept. A verdict (not linked, poisoned or panicking engine, parity mismatch) is latched. A transient failure is retried after 30 s.

### 4. Verification

`verify.sh` has an always-on `Go — gusset engine (cgo)` step. The DevCouncil host and this step build through DevCouncil's `rust/gusset-engine/cgo-env.sh`, which rebuilds the archive every time and keys Go's caches on its hash.

Five `NOT COVERED` lines that previously printed mid-log and never reached the verdict list now go through `notcovered`.

`verify.sh` runs `bench/paper/test_supplement.py` with the other bench tests.

## Installation & Verification

Sibling checkouts must be the commits in `scripts/module-pins.txt`. `scripts/fetch-modules.sh` will not move a checkout that is already at another commit.

This machine is darwin/arm64. The local binary is the engine-linked release build:

```bash
GOOS=darwin GOARCH=arm64 EVENT_NAME=workflow_dispatch INPUT_TAG=v0.0.6 \
  bash scripts/release-build.sh
cp dist/manvi-v0.0.6-darwin-arm64 ~/.local/bin/manvi
```

`scripts/release-build.sh` runs `gusset-check` before it accepts the artifact.

Check the installed version:

```bash
manvi --version
manvi gusset-check
```

`manvi --version` reports `v0.0.6 (-ldflags)` with the Git revision of the commit that was linked.

`native/` is unchanged since the v0.0.5 local install, so this build does not replace `manvi-desktop`.
