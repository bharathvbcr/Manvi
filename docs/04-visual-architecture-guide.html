Dual-Plane System Guide

A visual tour of how MANVI turns a language model into a coding agent you can audit: what runs where, what the policy gate decides, and why a turn can be trusted to have ended.

MANVI in four sentences. MANVI is a coding-agent harness: it runs the model loop, enforces what the agent may touch, and records everything. It is written in Go for the IO-bound parts and delegates the CPU-bound, determinism-critical parts to DevCouncil components written in Rust.
  • Components over a process boundary. Go execs dcstore, dcverify, dcgrep and devmap and exchanges JSON over stdio; none is ever linked.
  • Blocks are never invisible. A check that did not run, or a rule cleared by a grant, is always labelled; it never looks like a clean pass.
  • Evidence ends turns. The model saying "done" is not enough; a harness checkpoint verifies what the turn actually changed.
  • The log is the truth. History sent to the model is always re-projected from an append-only session log.

1. The Dual-Plane Architecture

MANVI splits work on the axis of IO-bound concurrency versus CPU-bound determinism. Go drives goroutines, provider streams and the terminal; Rust provides diff parsing, coverage analysis, repository search, code-graph extraction and the ACID SQLite lease store.

The rule of thumb for where a new piece of work belongs: if it is heavy parsing or matching that must behave identically every time, or needs a database invariant, it is a Rust component. If it waits on the network, a terminal or another process, it is Go. Tie goes to Go, because the Go module builds in seconds and a Rust build with tree-sitter grammars takes minutes. See COMPONENTS_AND_HARNESS.md.

Go Execution Plane

Concurrency & Interaction

The manvi binary. Static on Linux (musl); release builds link exactly one Rust archive, the Gusset policy engine. Beyond the standard library, the Go module takes only an allowlisted few packages (memguard, samber/mo) plus the pinned DevCouncil and Gusset modules.

  • manvi/llm Anthropic, Gemini, xAI, local models
  • manvi/gate Write & command policy ladders
  • manvi/grants Human & agent override ledger

Rust Analysis Plane

Deterministic Analysis

DevCouncil components, resolved from PATH as standalone binaries with a JSON-on-stdio contract. Usable by any coding agent or host, not only MANVI.

  • dcstore Tasks & SQLite lease mutex
  • dcverify Diff parser, rigor gates, coverage
  • dcgrep Ignore-aware search (ripgrep engine)
  • devmap AST code graph & adjacency
  • dc-glob CPython-fnmatch glob engine (library)
Process Boundary, Not CGO

Go execs the components, passing arguments and JSON over pipes. Mutual exclusion lives in SQLite's partial unique index, not in Go memory, and a crash in a component cannot corrupt the harness. The boundary is the process, not a fork per call: dcstore also runs as a long-lived serve session that answers many requests over one connection.

Components: never linked
The one linked archive. Since v0.0.6 release binaries link the Gusset engine, which answers every policy pattern question (secret paths, protected paths, planned-file globs, command allowlists). Its answers are held equal to Go's fnmatch by a CPython parity fixture and a fuzz differential. If the engine cannot answer mid-decision the result is a hard denial (path.engine_unavailable), never a guessed boolean; a question unanswered within 250 ms falls back to fnmatch. A CGO_ENABLED=0 build has no engine and decides with fnmatch. Verify a binary with manvi gusset-check.

Why this shape

Embeddable

One binary, one contract

The only external contract is fork/exec plus line-delimited JSON, so another application takes the harness without inheriting any component's dependency tree. manvi serve exposes the harness over NDJSON stdio for IDEs and host apps.

Fault isolation

Crashes stay on their side

A panic inside dcverify surfaces as a failed call with a non-zero exit. The harness treats an unparseable or failed response as a hard failure, never as an empty pass.

Independent updates

Swap one component

Because nothing is linked, a host can update devmap or dcstore without rebuilding the harness, or take only the subset it needs.

3. The Six-Rung Policy Ladder

Every file write and every shell command passes the same ladder. Blocks are overridable when appropriate, but never invisible: a check that did not run records that fact, and a grant that cleared a rule is branded on the tool output.

1
Workspace Boundary

Refuses any file write or command target that escapes the repository root: ../ traversal and absolute paths outside the workspace. This is the one rung that holds under every posture, including yolo.

path.outside_root
2
Hard Security Rules (ungrantable)

Credentials, .git internals, agent configuration and unsafe git or shell operations. No grant clears them. Attempting to issue one fails immediately with ErrUngrantableRule. They are switched off only by yolo or by explicitly setting policy.hard_rules.enabled=false, and that is recorded as degraded.

path.credential (.env*, *.pem, *.key, id_rsa) path.git_internal (.git/*) path.agent_config cmd.git.force_push cmd.git.bypass (--no-verify) command.too_long (128 KiB)
3
Soft Scope & Adjacency Rules

Does the change match the files the task declared in devcouncil_checkout_task, or sit inside the code-graph neighbourhood of one? A path in the same subsystem as a planned file, or a declared neighbour of one, is admitted; only past that does the soft rule fire.

scope.unplanned scope.neighbourhood command.no_lease command.not_allowed
4
Grants Ledger Consultation

Is there an active, unexpired grant matching this rule and target, with a non-empty justification? Grants are scoped and time-bounded (default maximum 15 minutes). An agent may clear most soft rules for itself, but never command.no_lease or command.not_allowed: arbitrary shell execution is how gates themselves could be subverted.

5
Posture Demotion

Under dev (the shipped default) a violated soft rule is allowed but reported as demoted. Under yolo soft rules are off. Under strict nothing is demoted and the decision falls through to rung 6.

6
Operator Escalation

Under strict in an attended TUI the operator is asked in a modal; approval issues a human grant and the write proceeds, denial blocks it. With no approver attached (CI, unattended) the soft rule blocks outright.

How the command gate differs from the write gate

A command line has two things to judge: the command and the files its redirections open. Redirect targets go through exactly the path a WriteFile call faces, so cmd > .env cannot be treated differently from writing .env directly. Redirect enumeration descends into $( ), backticks and process substitution; a target that cannot be resolved (> $HOME/x) is refused rather than skipped. The invariant: the gate's verdict on a command line is never more permissive than its verdict on the files that command writes.

Cost is bounded: lines over 128 KiB are refused before any rung reads them, a line may be judged to write at most 64 distinct paths, and heredocs and eval arguments are refused outright because their meaning is not in the text being judged. Running a script that lives on disk (make, pytest) is deliberately outside the ladder; the allowlist decides whether the command word may run.

Grant authority invariants
  • Hard rules are ungrantable by anyone, human or agent.
  • A reason is mandatory. Every grant carries a non-empty justification.
  • TTL is bounded. A zero or negative lifetime fails validation.
  • Literal vs glob matching is strict. A literal path cannot alias to a glob.

6. Evidence-Driven Turn Lifecycle

The agent loop in manvi/agent terminates on tangible evidence, not on the model declaring victory. History is always projected fresh from the append-only session log on disk.

StageComponentGuarantee & invariant
1. History projectionsession.Project()Messages are projected from the log each step. AssertModelVisible aborts the turn if anything the model sees lacks a log record, so in-memory drift cannot occur.
2. Pre-step waterfallbus.PreStepLets listeners compact context (appending ToolResultCompacted events, never rewriting history) or reject the step before any tokens are spent.
3. Streaming providerllm.Stream()Separates reasoning from text and tool calls; records each delta, token usage and the provider's replay state for deterministic resume.
4. Tool executiontools.Execute()Pre-execute waterfall, then the policy gate, then the tool body, then post-execute. The result carries its qualification (grant ID, demotion, degraded checks) back to the model and the log.
5. Termination evidenceagent.TurnStoppingWhen the model emits no tool calls, a serial checkpoint judges what the turn actually did before the loop is allowed to end.

The terminal checkpoint

  1. A listener supplies the reason. To keep a turn open it states what changed and what the model should do; the loop appends that text. It does not silently re-ask with an unchanged history.
  2. The inject is marked. It occupies the user role on the wire, but is recorded with Origin: harness, so transcripts and reports show the harness speaking, not the operator.
  3. Bounces are bounded. At most MaxCheckpointBounces (two) per turn. After that the turn closes and Outcome.BouncesExhausted records that the objection still stood.
  4. A failing check closes the turn as degraded. A check that could not run has asked for nothing and is never reported as a pass.

The harness's own listener (the end-of-turn check) skips turns that changed nothing, verifies the paths a mutating turn wrote, and escalates to an adversarial reviewer only after telling the model was not enough. manvi serve is out of scope: the host owns the model call, agent.Loop does not run, and the checkpoint never fires.

The session log invariant

On disk the log is one checksummed JSON document per generation (<id>.<generation>.json), written whole and linked into place atomically, so a corrupt write is refused rather than half-read. Each message records who authored it, so a verdict the harness handed back is never rendered as the operator's words.

7. SQLite Task Lease Concurrency

Multi-agent safety is enforced by the database, not by Go. Two agents can never both hold an active lease on a task, because SQLite refuses the second row. 

CREATE UNIQUE INDEX ux_task_leases_active ON task_leases (task_id) WHERE status = 'active';
  1. Acquire. dcstore opens BEGIN IMMEDIATE and inserts a lease row. A unique-index violation comes back as {"ok":false,"error":"task held by ..."}.
  2. Renew and release. Leases carry a token and expiry; heartbeats extend them and release frees them.
  3. Cancel cleanly. When a sub-agent tree is cancelled (for example Ctrl+C), MANVI calls dcstore release with a fresh, uncancelled context so the lock is freed for the next turn instead of lingering until expiry.
  4. Stay fast. A small pool of long-lived dcstore serve processes holds one SQLite connection each. A lease check drops from about 3.9 ms (fork/exec dominated) to about 0.03 ms p50 on an idle machine; under load the speed-up narrows, so treat it as one to two orders of magnitude.

8. Build, Dependencies & Failure Modes

A full source build needs Go 1.26, Rust 1.85+ and a C compiler (dc-store compiles SQLite from source rather than trusting the host's libsqlite3). The dependency set is a gate: verify.sh fails on any Go package outside the allowlist.

Go module

Small, audited surface

memguard seals credentials at rest, samber/mo gives optional values one spelling, and the ruleguard DSL is lint-only and excluded from every build. Everything else is the standard library, plus the pinned DevCouncil and Gusset modules.

Rust crates

Two external families

rusqlite (bundled) for the store, and ripgrep's engine crates for dc-grep. dc-glob and dc-verify have no external dependencies, and cargo audit runs on every gate.

Docs tooling

Dev-time only

Mermaid diagrams are parsed with the real grammar on node, provisioned by bun from bun.lock, and bun audit checks the lockfile. Nothing here reaches the manvi binary.

What happens when a component is missing

Missing binaryConsequence
dcverifySecret scanning, stub detection and diff coverage report as did not run in the decision's degraded list; they are never counted as passing.
dcstoreStore-backed tools fail hard: no leases, no tasks, no mutual exclusion. Under dev a Go-only build still drives turns, with writes landing as demoted.
dcgrepdevcouncil_grep refuses and names the build command and MANVI_GREP_BINARY. There is no Go fallback, because a second search implementation would answer differently, and a missing searcher reporting zero matches is worse than being unavailable.

Binaries are discovered through the MANVI_*_BINARY environment variables first, then PATH, then sibling build artifacts in crates/target/{release,debug}. manvi doctor reports what it found.
