# Releasing MANVI

A release is a `v<major>.<minor>.<patch>` tag. Pushing it runs `.github/workflows/release.yml`. The curated notes live in `docs/releases/<tag>.md`; the tag must name the commit that has them (`scripts/check-release.mjs --require-head`).

None of the workflows below has been run on GitHub yet. They are validated with `actionlint` and the script tests (`node --test scripts/check-release.test.mjs scripts/release-scripts.test.mjs`, part of `./verify.sh`). The first real release is the first real test.

## What a release contains

| File | Notes |
|---|---|
| `manvi-<tag>-darwin-amd64`, `-darwin-arm64` | Signed with a Developer ID certificate and notarized. Gusset engine linked. |
| `manvi-<tag>-linux-amd64`, `-linux-arm64` | Fully static (musl). Gusset engine linked. |
| `manvi-<tag>-windows-amd64.exe` | Built `CGO_ENABLED=0`: **no Gusset engine**. Not Authenticode-signed. |
| `<binary>.sbom.cdx.json` | One CycloneDX 1.5 SBOM per binary. |
| `SHA256SUMS` | SHA-256 of every binary and every SBOM, for `shasum -c`. |
| `PROVENANCE.json` | Commit, run, verify run, module pins, toolchain, digests. A record, not a signature. |

### Windows

The Go tree builds for `GOOS=windows` with `CGO_ENABLED=0` (checked with `go build ./cmd/manvi`; `verify.yml` also tests it on `windows-latest`). With cgo it does not: gusset supports only unix targets and fails a Windows build with a named error (`gusset/docs/platforms.md`), and the Go runtime's own cgo needs a MinGW toolchain this repository does not provide. So the Windows binary is the `CGO_ENABLED=0` build, with no Gusset engine linked. Policy decisions never use the engine on any platform (Go's fnmatch is the one matcher), so what Windows lacks is the engine's boundary self-check (`gusset-check`); the job runs `manvi version` instead. The release notes and the binary's SBOM (`manvi:gusset-engine: not linked`) say so. There is no Windows arm64 build.

### SBOM

Format: CycloneDX 1.5 JSON, because the common scanners read it and it carries a dependency graph, purls and an artifact hash. It is generated by `manvi/cmd/sbomgen` (standard library only) from what the toolchains already record: the Go build info embedded in the binary (what `go version -m` prints) and `cargo metadata --locked --filter-platform <triple>` for the Gusset engine's crates. It refuses to write an SBOM that disagrees with the binary: a cgo binary without Rust crates, or Rust crates on a non-cgo binary. `check-release.mjs` refuses to publish an SBOM that is not CycloneDX or does not carry the SHA-256 of its binary.

The DevCouncil and gusset modules are linked from sibling checkouts through `replace` directives, so build info records no revision for them. `release-sbom.sh` passes `scripts/module-pins.txt` (`-pins`) and the pinned commit is recorded as the component version and a `go:revision` property; Rust path crates get `cargo:revision` the same way. A replaced module or path crate with no pin fails the SBOM step.

Run it by hand against a binary: `go -C manvi run ./cmd/sbomgen -binary <file> -tag <tag> -o <out>` (add `-pins scripts/module-pins.txt` for a build that links the sibling modules, and `-cargo-metadata` and `-rust-target` for a binary with the engine).

## macOS signing and notarization

`scripts/release-sign-macos.sh` runs `codesign` (hardened runtime, secure timestamp) and `xcrun notarytool` on each darwin binary. The owner adds six secrets under Settings, Secrets and variables, Actions (repository or an environment secret):

| Secret | Value |
|---|---|
| `APPLE_CERTIFICATE_P12_BASE64` | `base64 -i DeveloperIDApplication.p12`: the Developer ID Application certificate with its private key |
| `APPLE_CERTIFICATE_PASSWORD` | The password chosen when exporting the `.p12` |
| `APPLE_SIGNING_IDENTITY` | The identity name, for example `Developer ID Application: Your Name (TEAMID)` (`security find-identity -v -p codesigning`) |
| `APPLE_ID` | The Apple ID that owns the team |
| `APPLE_TEAM_ID` | The 10-character team ID |
| `APPLE_APP_PASSWORD` | An app-specific password for that Apple ID (appleid.apple.com) |

Without all six, the **gate job fails before anything is built**, naming the missing secret names. The one exception is a deliberate `workflow_dispatch` run with `allow_unsigned` ticked. That run builds the darwin binaries named `...-darwin-<arch>-UNSIGNED`, the notes start with an UNSIGNED banner, and the job log carries a warning. A tag push cannot set the input, and `workflow_dispatch` runs are dry runs that publish nothing, so an unsigned release cannot reach GitHub Releases.

The Apple ID app password never appears in a command line: it is stored in the temporary keychain with `notarytool store-credentials` (read from its secure prompt, run under `script` for a pty) and later calls use `--keychain-profile`. `security` accepts the `.p12` password and keychain password only as arguments, so those two are visible in `ps` on the runner for the moment they run; GitHub masks them in logs but not in `ps`. The keychain password is random per run and the runner is a single-job VM. The certificate key is imported with `-T /usr/bin/codesign`, not allow-any-application. The `store-credentials` pty step has not been run against Apple.

A bare Mach-O binary cannot have a notarization ticket stapled, so the ticket is not inside the file. Gatekeeper looks it up online on first launch; a download opened on a machine that is offline at that moment is not verified until it is online.

The Windows binary is not signed. Authenticode signing needs a different certificate and was not part of the decision.

## Rolling back a release

`.github/workflows/rollback-release.yml` (Actions, rollback-release, Run workflow). Inputs:

- `tag` and `confirm`: the tag to withdraw, typed twice. A mismatch changes nothing.
- `mode`: `prerelease` (default) or `draft`. Either removes the release from "latest".
- `delete_assets`: also delete the assets. Off by default; cannot be undone.
- `delete_tag`: also delete the git tag. Off by default and separate from everything else; the tag is never deleted otherwise.
- `previous_tag`: the release to restore as latest. Default: the highest-semver published, non-draft, non-pre-release release other than `tag` (by version, not publish date).
- `dry_run`: print the `gh` commands without running them. **On by default**; untick it to withdraw for real.

The release is marked first, assets and tag removed afterwards only if asked, and the previous release is made latest. If no earlier published release exists the run warns and still withdraws. To publish a fixed release afterwards, use a new tag; do not reuse the withdrawn one unless you also deleted it. Logic: `scripts/release-rollback.sh`.
